# 「我们的回忆」独立模块设计

> 配套原型：`memories-prototype.html`（单文件、可直接双击打开；`?demo=detail|editor|album|empty|confirm|save|undo` 看各状态与保存/撤销自检）
> 视觉稿：`shots/m-list-390.png`、`m-detail-390.png`、`m-editor-390.png`、`m-album-390.png`
> 拆解背景：`01-bubu-room-decomposition.md`

---

## 1. 定位

**一段回忆 = 一个单位**，不是「一张照片的附属文字」。

现在的实现是 photo-first：`gallery()`（`space-app.js:276`）先列出照片索引，再把 `memories` 按 `photoName` 贴上去；没照片的文字回忆只能当二等公民，照片还没传完的回忆干脆不显示（旧版），或者靠本机预览顶住（本地未上线版）。这个模型在「先写字、后补照片」「同一张照片想换标题」时都会别扭。

新模型：**memory 是主体，photo 是它的一个可选附件**。这样空状态、只有文字、上传中、删除、换图，都是一条记录的状态变化。

---

## 2. 目标与非目标

**目标**
- 3 秒记一条：从首页到「保存」不超过 3 次点击
- 1 秒找到：按时间轴 / 相册两种方式，筛选「有照片 / 只有文字 / 我写的」
- 看大图：详情页整屏照片 + 全文 + 前后翻
- 删错了能救：删除后 5 秒撤销
- 离线可看：上次同步的列表 + 已解密的照片
- 两台设备一致：写、改、删都不互相覆盖

**非目标（这一版不做）**
- 评论 / 点赞 / 分享到外部
- 九宫格多图（v1 一条一张，模型预留 `photos[]`）
- 地图、地点联想、EXIF 展示
- 全文搜索（P2 再做）

---

## 3. 三个真实场景

1. **深夜想记一句话**：躺在床上，不想开电脑。首页长按布布 → 记一段 → 只写文字 → 保存。整个过程不离开手指可及的范围。
2. **翻去年的今天**：在回忆页沿时间轴往下滑，停在「2025 年 5 月」，点开一张海边照片看大图，再左右滑看相邻两条。
3. **换手机**：新设备打开站点 → 输空间密码 → 列表直接出现（文档解密 + 照片按需解密），不需要重新登录任何账号。

## 4. 信息架构

```
首页 ──(卡 / 导航 / 布布菜单)──► #/memories            列表（时间轴｜相册）
                                   ├─ ＋ 记一段 ──► #/memories/new     编辑
                                   └─ 点卡片 ────► #/memories/:id     详情
                                                       ├─ 编辑 ──► #/memories/:id/edit
                                                       └─ 删除 ──► 确认面板 → 撤销
```

- **入口收敛为 1 个主入口 + 3 个快捷方式**：底部导航「回忆」/ 首页「我们的回忆」卡 / 首页统计卡「最近回忆」/ 布布菜单「记一段」。全部落到同一路由。
- **返回**：列表 ← 首页；详情 ← 列表；编辑 ← 详情（新建则 ← 列表）。微信返回键逐层退，不退出站点。
- 详情支持左右滑切换相邻回忆；下滑关闭（可选，P1）。

### 5.3 编辑页

```
┌──────────────────────────────┐
│ 取消        新回忆       保存 │
│ ┌──────────────────────────┐ │
│ │        ＋ 添加一张照片     │ │
│ └──────────────────────────┘ │
│ 标题                     0/40 │
│ [ 给这段回忆起个名字        ] │
│ 那天发生了什么          0/300 │
│ [ 风很大，你把围巾分了……   ] │
│ 日期            地点（可选）  │
│ [2026-11-18]   [ 在哪 ]      │
│ 这一条是谁写的                │
│ [●小猫] [●小鱼] [●我们]      │
│ ⓘ 照片会压到长边 1400 像素…  │
└──────────────────────────────┘
```

| 字段 | 规则 |
| --- | --- |
| 照片 | 可选；选完立即压缩并显示本机预览（不传完也能保存） |
| 标题 | 可选，40 字；为空时按「有照片 → 一段回忆 / 没照片 → 记一笔」自动命名 |
| 正文 | 可选，300 字；自动增高，显示计数 |
| 日期 | 默认今天，**允许回填过去**（回忆常常是补写的） |
| 地点 | 可选，20 字，纯文本，不做定位 |
| 作者 | 小猫 / 小鱼 / 我们；本机记住选择（`catfish-identity-v1` 已有） |
| 保存 | 至少有一项内容才可点；保存后回列表并滚动到新卡 |
| 草稿 | 输入即存 `localStorage`，微信杀进程后重进能恢复；保存后清空 |

**照片状态机**

```
空 ──选图──► 压缩中 ──► 就绪(本机预览) ──保存──► 上传中 ──► 已入索引
                 │                                  │
                 └─失败: 换一张                      └─失败: 标记 pending，进重试队列
```

- 压缩在 `PhotoStore.prepare()` 里完成（长边 1400 / 质量 .82，约 150KB）。
- 上传失败不阻塞文字：memory 先写入云端（`photoName` 留空或占位名），照片进 `catfish-photo-queue-v1`，联网后补传并回填。
- 删除顺序：先删索引 → 再删 blob；失败只提示，不阻塞。

**校验与错误**

| 情况 | 提示 |
| --- | --- |
| 三项全空 | 「写点什么，或者放一张照片」 |
| 没有写入密钥 | 「这台设备还没有写入密钥：照片先在本地，贴好后自动补传」 |
| 压缩失败（HEIC 等） | 「这张照片用不了，换一张 JPG/PNG 试试」 |
| 云端写失败 | 输入保留 + 草稿保留 + 「网络不通，已存本机，稍后自动补」 |

### 5.4 相册视图

- 3 列方格、1:1，圆角 12，底部渐变压字：`11/06 · 第一次一起看海`（单行省略）。

- 点击进详情；不分组，按时间倒序；加载更多用「滚到底自动追加 30 条」。

### 5.5 空状态

## 6. 数据模型

### 6.1 存储

仍然是 `data` 分支的 `docs/memories.json`（密文），**不改 sync.js 的加密与提交方式**。

```jsonc
{
  "items": [
    {
      "id": "m0x3k9f2a",          // uid()，客户端生成，永不变
      "at": 1793606758059,        // 回忆发生时间（可回填），不是写入时间
      "title": "第一次一起看海",
      "text": "风很大……",
      "photoName": "p20261106-2110-ab12.jpg",  // 空字符串 = 纯文字
      "place": "青岛",             // 可选
      "by": "cat",                // cat / fish / us
      "updatedAt": 1793606799000, // 该条最后修改时间，用于合并
      "deletedAt": 0              // >0 = 墓碑（软删除），默认 0
    }
  ]
}
```

**兼容**：现有记录正好是 `{id, by, at, title, text, photoName}`，新字段全部可选，**不需要迁移脚本**。读取时归一化：缺 `updatedAt` 用 `at`，缺 `place` 用 `''`。

**索引**：照片仍由 `PhotoStore` 的 `docs/media.json` 管理（`{items:[{name,at,size,sha}]}`），memory 只存 `photoName`，两边通过文件名关联。这样照片上传/删除与回忆的写入互不阻塞。

### 6.2 合并策略（两台设备同时写）

`sync.js` 现在是整份 `payload` 乐观锁（sha 冲突重读重试），没有字段级合并。回忆改成**按 id 合并**，在 `Space.mutate` 的 updater 里做：

```
读取远端 items + 本地 items
按 id 建 map
同一 id：updatedAt 大的胜；相等时保留远端
本地有、远端没有：加入（新增）
远端有 deletedAt>0：删除（除非本地同 id 的 updatedAt 更晚）
其它：保留远端
```

- 删除用墓碑而不是直接 `filter` 掉，否则离线的另一台会把这条「加回来」。
- 墓碑保留 30 天；每次保存时顺手清理 `deletedAt < now-30d` 的条目。
- 照片 blob 的删除放在墓碑之后（30 天后或手动清理），避免撤销/并发时破图。

> 如果嫌墓碑复杂，P0 可以先做「硬删除 + 5 秒本机撤销」，把墓碑放到 P1；但两台设备同时在线时会有极小概率「删了又回来」，要在验收里写明。

## 7. 照片管线

| 阶段 | 调用 | 结果 |
| --- | --- | --- |
| 选择 | `PhotoStore.prepare(file)` | `{blob, preview, width, height}`，本机 objectURL |
| 编辑中 | 内存 `pendingPhoto` | 不写盘，不占仓库 |
| 保存 | `PhotoStore.upload(blob, name)` | 加密上传 `media/<name>` → 更新 `media` 索引 |
| 列表 | `PhotoStore.cached()` + `data-photo` | 已在 IndexedDB 的直接显示 |
| 详情 | `PhotoStore.url(name)` | 本机预览 > 内存 > IDB > 下载解密 |
| 删除 | `PhotoStore.remove(name, sha)` | 先索引后 blob |

**要补的只有一件事：照片失败队列。** 现在 `Space` 的队列只收文档，照片文件不入队（`sync.js` 里 `enqueue` 只处理 key/payload）。新增 `catfish-photo-queue-v1`，结构 `[{name, blobKey?, at}]`，照片 blob 太大不能进 localStorage——用 IndexedDB 存待传 blob，队列只存 name；`refresh()` 时先补照片再补文档。

## 8. 离线与同步

| 场景 | 行为 |
| --- | --- |
| 离线打开 | 列表来自 `catfish-space-cache-v3`；照片来自 IDB；顶部细条提示 |
| 离线新增 | 先本地插入（`S.apply` 语义），文档进队列，照片进照片队列 |
| 恢复网络 | `refresh()` → 先 flush 照片 → 再 flush 文档 → 拉最新 |
| 对方新增 | 45s 轮询 / 切回页面时 `refresh`，列表增量插入并高亮 1.5s |
| 冲突 | 按 id 合并（见 6.2），不整份覆盖 |
| 删除 | 墓碑 + 撤销窗口；30 天后清照片 |

## 10. 无障碍与移动端

- 列表卡片 `role="button" tabindex="0"`，Enter/Space 打开；详情/编辑是 `role="dialog" aria-modal="true"`，打开时焦点移入，Esc 关闭，关闭后焦点回到触发元素。
- 保存状态用 `aria-live="polite"`（「已保存」「正在上传」）。
- 图片 `alt` 用标题，不用文件名。
- 安全区：`env(safe-area-inset-bottom)` 给 FAB 和底部面板留位；`100dvh` 而不是 `100vh`。
- 键盘：编辑页用 `visualViewport` 监听，键盘弹出时保存按钮仍可见（sticky 头部）。
- 输入不触发页面缩放：`font-size ≥ 16px` 或 `maximum-scale` 保持现状（站点已锁 `maximum-scale=1`，但 iOS 仍建议 16px 以上）。

- [ ] 新建：只写文字 / 只放照片 / 两者都有，都能保存
- [ ] 照片上传中关掉页面，重进后仍在，联网自动补传
- [ ] 列表 7 段、筛选「只有文字」1 段，数字一致
- [ ] 删除后 5 秒内撤销，条目和照片都回来
- [ ] 两台设备：A 新增，B 在 45s 内出现；A 删除，B 不复活
- [ ] 离线新增，恢复网络后自动补传，不重复
- [ ] 详情正文完整显示，不被截断
- [ ] 相册视图点任意格进详情
- [ ] 空状态、筛选空、加载骨架三种状态都可复现（`?demo=empty`）
- [ ] 键盘弹出时「保存」仍可点
- [ ] VoiceOver/TalkBack：卡片可读、按钮有名字、Esc/返回可关
