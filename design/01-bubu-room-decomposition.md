# 布布房间功能拆解

> 对象：线上站点 <https://catandfish111.github.io/CAT-FISH/> 的「布布」浮层
> 目标：把混在一个浮层里的 7 个模块按数据归属、使用深度、返回语义拆开，让「回忆」独立成一页
> 配套：`02-memories-module.md`（回忆模块设计）、`memories-prototype.html`（可点击原型）

---

## 1. 它现在其实是一个「四合一」

「布布房间」并不是一个功能，而是四层东西被塞进了同一个 DOM 容器：

| 层 | 内容 | 数据 | 代码 |
| --- | --- | --- | --- |
| L1 陪伴 | 待机 GIF、点一下换动作、拖拽、长按、双击、右键菜单、自动轮换 | 本机 `localStorage` | `app.js:229-572` |
| L2 导航 | 总览 / 动作 / 便签 / 回忆 / 番茄钟 / 提醒 / 设置 七个 tab；首页四张卡、底部四个导航也指向它 | 无 | `app.js:391-499`、`index.html:127-157` |
| L3 云模块 | 便签、回忆、愿望、提醒、番茄钟、空间密码 | 云端 `data` 分支 | `space-app.js:333-574` |
| L4 设置 | 声音、安静、自动轮换、气泡、身份、写入密钥、改密码、自检、同步状态 | 本机 + 云端混合 | `app.js:462-473`、`space-app.js:503-544` |

一个 390px 宽、最高 72dvh 的浮层（`styles.css:209`）同时承担这四层，问题不是「不好看」，而是**每一层的生命周期、数据归属、返回语义都不一样，却被同一个 `innerHTML` 管着**。

## 2. 功能清单与归属

| 功能 | 数据 | 现入口 | 需要的空间 | 使用深度 | 建议归属 |
| --- | --- | --- | --- | --- | --- |
| 待机 / 随机动作 / 拖拽 / 长按 | 本机 | 首页右下角 | 无 | 常驻 | **留在布布**（陪伴层） |
| 动作库（34 个 GIF） | 本机 `assets/bubu/` | 长按 → 动作 | 中（4 列网格） | 一瞥 | 留在布布，半屏面板 |
| 便签 | `docs/notes.json` | 长按 / 首页 / 底部导航 | 小 | 快速一瞥 | 独立小面板（快捷输入） |
| **回忆** | `docs/memories.json` + `media/*` | **3 个入口** | **大（列表 + 详情 + 编辑）** | 长时间浏览 | **独立页面**（见 02） |
| 愿望 | `docs/wishes.json` | 首页卡 / 底部导航 | 中 | 浏览 + 勾选 | 独立面板 |
| 提醒 | `docs/reminders.json` | 长按 → 提醒 | 中 | 偶尔 | 独立面板 |
| 番茄钟 | `docs/timer.json` | 长按 / 首页倒计时 | 小 | 一瞥 | 小面板 |
| 设置（静音/自动/气泡/身份） | 本机 | 长按 → 设置 | 小 | 一次性 | 并入「布布偏好」 |
| 设置（写入密钥/改密码/自检/同步） | 本机 + 云端 | 同上 | 大 | 一次性但关键 | **独立设置页** |
| 总览（hub） | 无 | 长按 | 中 | — | 取消，改成快捷动作 |

## 3. 现在具体卡在哪

1. **空间不够，硬塞**：回忆是两列卡片 + 顶部编辑器（`space-app.js:333-382`），在最高 590px 的浮层里，键盘一弹就盖住「保存」；而设置里的写入密钥、自检又是一屏放不下的长内容。
2. **双渲染器共管一个 DOM**：`app.js` 负责「总览 / 动作」，`space-app.js` 负责其余五个（`app.js:408`、`space-app.js:547`）。tab 的点击被绑了三次（`app.js:474-484` 的普通绑定 + 捕获阶段兜底），每次点击都重新 `innerHTML`，正在输入的便签/密钥会被清空。
3. **数据归属混杂**：布布偏好只该在本机（`app.js:289-312`），空间密码却和静音开关在同一个「设置」里；`refreshUI` 在编辑器打开或输入中直接 `return`（`space-app.js:586`），对方刚写的内容静默不出现。
4. **入口语义重复**：首页四张卡、底部四个导航、长按菜单、双击、右键菜单，全都落到同一个浮层；用户无法预期「点了会去哪、返回会到哪」。
5. **微信返回键不认浮层**：浮层是 `<section hidden>`，返回键不会关它，会直接退出站点——这是微信里最伤体验的一条。
6. **长按是唯一入口但没有任何提示**（640ms，`app.js:537`），7 个 tab 在 390px 宽下还要横向滚动（`styles.css:216`），最后一个「设置」默认看不见。

---

## 4. 拆解原则

1. **按数据归属分**：本机偏好不进云端面板；云端共享内容不塞进「设置」。
2. **按停留时长分**：一瞥（便签、倒计时）用半屏；浏览（回忆、愿望）用整页；管理（密钥、密码）用整页。
3. **按返回语义分**：需要「返回上一页」的，必须是 hash 路由页面；只有「关掉就回到原处」的，才用浮层。
4. **一个功能只有一个主入口**：其余入口是快捷方式，最终落到同一个路由。

## 5. 拆完的结构

```
首页
├─ 布布（陪伴层，纯本地）
│   ├─ 点一下 → 随机动作
│   ├─ 拖拽 / 长按 640ms → 快捷菜单（4 项，不再是 7 个 tab）
│   │     记一段回忆 · 贴张便签 · 开始专注 · 动作库
│   └─ 长按菜单里的每一项 = 跳到对应路由 / 打开对应半屏
│
├─ 首页卡片 → #/memories、#/wishes、#/utilities
├─ 底部导航 → 首页 / 回忆 / 愿望 / 更多
│
└─ 路由（hash）
    #/                 首页
    #/memories         回忆列表      ← 独立页
    #/memories/new     写一段回忆    ← 独立页
    #/memories/:id     回忆详情      ← 独立页
    #/wishes           愿望
    #/notes            便签（半屏）
    #/reminders        提醒（半屏）
    #/timer            番茄钟（半屏）
    #/actions          动作库（半屏）
    #/settings         设置（整页：密钥 / 密码 / 自检 / 同步）
```

**没有「总览」了**：快捷菜单本身就是总览；也没有横向 tab 条，页面标题就是层级。

## 6. 路由与返回键（微信重点）

最小实现（约 30 行，不引框架）：

```js
var routes = {
  '':           showHome,
  'memories':   showMemories,
  'memories/new': showMemoryEditor,
  'wishes':     showWishes,
  'settings':   showSettings
};
function parse() {
  return location.hash.replace(/^#\/?/, '').split('/');
}
window.addEventListener('hashchange', render);
function go(path) {
  if (location.hash === '#/' + path) return;
  location.hash = '#/' + path;   // 产生一条历史记录
}
```

- 打开 `#/memories` 后按微信/浏览器返回：先触发 `hashchange` 回首页，**不会退出站点**。
- 详情用 `#/memories/:id`，刷新后仍能回到同一条（前提是先过密码门，见 02 第 11 节）。
- 浮层（便签/提醒/番茄钟/动作库）不写历史，关闭就是关闭；只有整页才进历史。
- 路由切换只做 `hidden` / class 切换，不重建 DOM，避免重复绑定与输入丢失。

## 7. 迁移顺序（每步都能单独上线）

| 步骤 | 改动 | 风险 |
| --- | --- | --- |
| 1 | 新建 `router.js` + `memories.js` + `memories.css`，回忆页先用只读列表（数据仍来自 `Space` / `PhotoStore`） | 低；不影响旧面板 |
| 2 | 首页卡 / 底部导航 / 最近回忆卡改为 `go('memories')`，旧面板入口暂时保留 | 低 |
| 3 | 布布长按菜单改成 4 项快捷动作；删掉面板里的「回忆」tab | 中；要同步删 `renderMemories` 相关分支 |
| 4 | 设置拆成独立页，面板只留「布布偏好」 | 中；密码/密钥流程要回归测试 |
| 5 | 删除 hub 与横向 tab 条，`space-app.js` 只保留数据 API | 低 |

**数据分支完全不动**：`data/v1/docs/*.json` 的结构不变，旧设备打开仍能读写；新页面只是换了一种渲染方式。

> ⚠ 上线新文件前必须把 `router.js`、`memories.js`、`memories.css` 加进 `tools/deploy.js` 的 `FILES`（`tools/deploy.js:21-30`），否则 GitHub Pages 上会 404——部署脚本只推那 8 个白名单文件。
